# 3DS - 리팩

게임 파일과 한글패치를 병합하는 탭입니다.

!!! danger "키셋 필수"
    이 기능은 3DS 키셋이 반드시 있어야 동작합니다. 키셋 구하는 방법은 [실행 및 키파일 설정](installation.md)을 참고하세요.

## 화면 구성

- **롬파일** — `.3ds`, `.cci`, `.cia` 파일을 드래그 앤 드롭
- **한글패치 / xdelta (폴더 or zip, 7z)** — 한글패치 폴더 또는 zip/7z 압축파일을 드래그 앤 드롭
- **작업 폴더** — 언팩 루트 폴더이자, 결과 파일이 생성될 폴더
- **언팩 / 리팩(폴더 기반) / 언팩 + 리팩(스트리밍 기반)** 버튼
- **롬 정보** — 롬파일을 지정하면 아이콘, 타이틀명, 배급사, 제품 코드, 지역, 암호화 여부가 자동으로 표시됩니다.
- **진행률** — 진행률, 속도, 경과 시간

## 사용 방법

한글패치 배포 방식에 따라 크게 3가지 케이스로 나뉩니다. 케이스별로 진행 방법이 다르니 확인 후 진행하세요.

### 케이스 1) 패치 파일이 xdelta 하나뿐인 경우

3DS는 통파일(3ds, cci, cia)로 diff 패치를 만들어도 용량이 크지 않기 때문에, 패치 파일이 xdelta 같은 diff 기반 파일 하나로만 배포되는 경우가 있습니다. (예: 세계수의 미궁 4)

이 경우는 [3DS - 리팩] 탭이 아니라 [패치] - [일반] 탭에서 진행하면 됩니다.

결과 파일은 롬파일이 있는 폴더 하위의 `output` 폴더에 생성됩니다.

### 케이스 2) LayeredFS 방식 (대부분의 한글패치)

LayeredFS는 폴더 방식으로, 실행 중에 실시간으로 게임 파일을 교체해주는 구조입니다. 실기와 에뮬레이터에서 동작 방식이 조금 다르지만, RomForge로 리팩해두면 별도로 설정할 게 없으니 신경 쓸 필요는 없습니다.

**대부분의 3DS 한글패치가 이 케이스입니다.**

보통 압축파일 형태로 배포되며, 내부에 `exefs`, `romfs` 폴더가 보이고 루트에 `code.ips` 파일이 있을 수 있습니다.

!!! tip "code.ips는 자동 처리됩니다"
    `code.ips`가 보인다고 [패치] - [일반] 탭에서 `exefs/code.bin`을 따로 패치할 필요는 없습니다. [3DS - 리팩] 탭에서 리팩하면 자동으로 패치가 적용됩니다.

[3DS - 리팩] 탭에서 진행하면 됩니다. 최신 버전에서는 한글패치에 zip, 7z 압축파일을 그대로 지정할 수 있어서 미리 압축을 풀 필요가 없습니다.

작업 폴더에 CCI 파일로 결과물이 생성됩니다.

### 케이스 3) 내부 파일 단위 xdelta (기타 케이스)

드물지만 컬드셉트 리볼트처럼, xdelta로 배포되는데 전체 3DS 파일 기준이 아니라 내부 파일 하나만을 대상으로 하는 경우가 있습니다. RomForge는 이 방식도 지원합니다.

[3DS - 리팩] 탭에서 진행하면 되지만, 사전 작업이 하나 필요합니다. xdelta 파일만 봐서는 어떤 파일을 패치해야 하는지 알 수 없기 때문에, 폴더를 다음과 같은 구조로 만들어줘야 인식합니다.

```
romfs\CULDCEPT.DAT.xdelta
```

즉 `패치할 원본 파일명.xdelta` 형식으로 만들면 RomForge가 알아서 찾아서 패치하고 리팩합니다. 폴더 대신 zip 압축파일로 만들어도 동일하게 동작합니다.

정상적으로 처리되면 로그에 `romfs 패치 적용 완료: 1개 파일`처럼 표시됩니다.

암호화된 롬은 자동으로 복호화한 뒤 리팩이 진행됩니다.

!!! tip "언팩 + 리팩(스트리밍 기반)을 쓰세요"
    이 방식은 물리 디스크에 언팩하지 않고 메모리 상에서 바로 처리하기 때문에 훨씬 빠릅니다. SSD 수명 보호와 속도, 둘 다 챙길 수 있어 이 방식을 우선 사용하는 것을 추천합니다.
